## コードのコメントの規則

Gleam の `//`、`///`、`////` と Erlang の `%` のコメントに適用する。

### 書くこと

- 全関数と全型に簡潔な Doc コメント（`///`）を書く。
- コメントは日本語で書く。ログ文字列、識別子、エラーメッセージは英語のままにする。
- Doc には契約（何を受けて何を返すか、失敗の意味）と、コードから読めない不変条件と理由だけを書く。
- モジュール Doc（`////`）は、責務と、そのモジュールを変える人が守る不変条件と、詳しい説明のある docs の節への 1 行の参照にする。
- 同じ規則は 1 か所（型の Doc か、規則を実装する関数の Doc）にだけ書き、ほかからは名前で参照する。

### 書かないこと

- シグネチャ、型、直下のコードの手順や `case` の表の言い直し。
- マージした時点の動作でないもの。行番号、issue 番号、プランの項番、経緯（「以前は」「従来どおり」「〜に変えた」）、将来の予定、後続 issue で配線される動作。
- 呼び出し元の列挙（「〜が使う」「〜のために公開する」）。検査するテストの名前と、テストの都合（「テストが呼べるよう公開する」）。ただし秘密の扱いのように、読み手の判断を変えるものは書く。
- docs/ に書いてある説明の複写。
- 実測値、実験の記録、OTP などの出典つきの論証。これらは docs/（主に `docs/design-decisions.md`）に置く。

### 例

呼び出し元とテストを列挙した Doc（悪い）:

```gleam
/// ラベルの一覧を読む。起動時に `app` が、管理 UI の設定ページが使う。
/// `label_store_test` の `load_labels_test` が検査するので公開する。
pub fn load_labels(db: Connection) -> Result(List(Label), StoreError)
```

契約だけを書いた Doc（良い）:

```gleam
/// ラベルの一覧を名前の順で読む。DB に届かなければ `Error(Unreachable)` を返す。
pub fn load_labels(db: Connection) -> Result(List(Label), StoreError)
```

docs を複写したモジュール Doc（悪い）:

```gleam
//// ラベルのキャッシュ。起動時に全件を読み、変更の通知で入れ替える。通知が
//// 届かなかったときは 30 秒ごとの読み直しで追いつく（手元の計測で 1 万件を
//// 120ms で読む）。docs/architecture.md の「ラベル」と同じ説明を以下に続ける。
```

責務と不変条件と参照だけのモジュール Doc（良い）:

```gleam
//// ラベルのキャッシュ。書き込みは DB が先で、キャッシュは DB から読み直した値でだけ
//// 入れ替える。詳しくは docs/architecture.md の「ラベル」。
```

### 機械の検査

コメントを足した・変えたファイルは `sh dev/check_comments.sh <作業ツリー> <ファイル>...` で確かめる。
出た行のうち、自分が足した・変えた行を直す（ファイルに元からある行は直さない）。
一致が無ければ 0 で終わる。
